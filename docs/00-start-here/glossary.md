# Glossary

Short, practical definitions of terms used across this handbook. Where it helps, each entry says where you will meet the term on shift.

!!! abstract "At a glance"
    - Audience: everyone, especially new L1 analysts
    - Time to read: reference, search with Ctrl+F
    - Outcome: you can read any page, case note or vendor alert without getting stuck on jargon

!!! tip "Use it on shift"
    When a case note or alert uses a term you do not know, look it up here before you escalate. If a term is missing, add it to your internal copy and suggest it upstream.

## A-C

| Term | Meaning |
|------|---------|
| Account takeover (ATO) | An attacker gaining control of a legitimate user account, usually via stolen credentials or session tokens. Common trigger for identity playbooks. |
| Adversary-in-the-middle (AiTM) | Phishing that proxies the real login page to steal session cookies, bypassing most multi-factor prompts. |
| Alert | A signal generated by a rule or tool that something may be wrong. Not yet confirmed. |
| Alert fatigue | Loss of attention caused by too many low-value alerts. Leads to missed true positives. |
| Allowlist | A list of known-good items (IPs, hashes, users) excluded from a rule. Each entry needs an owner and expiry date. |
| Anomaly detection | Detection based on deviation from a learned baseline rather than a fixed pattern. |
| Asset inventory | List of hosts, accounts, applications and owners. Triage depends on it ("whose server is this?"). |
| Attack surface | Everything an attacker can reach: internet-facing services, users, third parties, APIs. |
| ATT&CK (MITRE ATT&CK) | Public knowledge base of attacker tactics and techniques, used to map detection coverage. Technique IDs look like `T1110` (Brute Force). |
| Baseline | Normal behaviour for a user, host or network, used to spot anomalies. |
| Beaconing | Regular, periodic outbound connections from malware to its command-and-control server. |
| Blast radius | How far an incident could spread: affected users, hosts, data and systems. |
| Blocklist / denylist | A list of known-bad items to block or alert on. |
| Brute force | Repeated guessing of passwords against one account (ATT&CK T1110.001). |
| Business email compromise (BEC) | Fraud using a compromised or spoofed business mailbox, often to redirect payments. |
| Case | The record that tracks an investigation: alerts, evidence, notes, actions, owner. |
| Chain of custody | Documentation of who handled evidence and when, needed if evidence may go to court. |
| CISO | Chief Information Security Officer: senior leader accountable for security. |
| Cloud Security Posture Management (CSPM) | Tooling that finds misconfigurations in cloud accounts (public storage, open security groups). |
| Command and control (C2) | Infrastructure an attacker uses to send commands to compromised hosts. |
| Containment | Actions that stop an incident from spreading: isolate host, disable account, block IP. |
| Correlation rule | A SIEM rule that combines several events (for example many failures then a success) into one alert. |
| Coverage map | A view of which ATT&CK techniques your detections cover, and how well. |
| Credential stuffing | Trying leaked username/password pairs across many accounts, usually from many IPs. |
| Crown jewels | The most valuable systems and data. Alerts touching them get higher severity. |
| CVE | Common Vulnerabilities and Exposures: public identifier for a known vulnerability, for example `CVE-2024-12345`. |
| CVSS | Common Vulnerability Scoring System: 0-10 severity score for vulnerabilities. Exploitability matters more than the raw score. |

## D-H

| Term | Meaning |
|------|---------|
| Dark web monitoring | Watching criminal forums and leak sites for your domains, credentials or data. |
| Deception / honeytoken | Fake assets (accounts, files, hosts) that should never be touched; any use is a high-confidence alert. |
| Detection-as-code | Managing detection rules like software: version control, peer review, automated tests. |
| Detection engineering | The discipline of designing, testing, deploying and tuning detections. |
| DFIR | Digital Forensics and Incident Response. |
| DLP | Data Loss Prevention: controls that detect or block sensitive data leaving the organisation. |
| DMARC / SPF / DKIM | Email authentication standards. Failures help spot spoofed senders in phishing triage. |
| DNS tunnelling | Hiding data or commands inside DNS queries, often seen as long, random subdomains. |
| Dwell time | Time from initial compromise to detection. Shorter is better. |
| EASM | External Attack Surface Management: continuous discovery of your internet-facing assets. |
| EDR | Endpoint Detection and Response: agent on hosts that records activity and can isolate the machine. |
| Enrichment | Adding context to an alert: asset owner, user role, IP reputation, geolocation. |
| Eradication | Removing the attacker's foothold: malware, persistence, rogue accounts. |
| Escalation | Passing a case to a higher tier or to management because of severity or skill needed. |
| Event | Any recorded occurrence in a log. Most events are harmless. |
| Exfiltration | Unauthorised transfer of data out of the organisation (ATT&CK tactic TA0010). |
| False negative | A real attack that produced no alert. The most dangerous outcome. |
| False positive (FP) | An alert that fired but was not malicious. Always record the reason. |
| Forensic image | A bit-for-bit copy of a disk or memory, taken for investigation. |
| Hash | A fingerprint of a file (SHA-256 recommended). Used to look up malware. |
| Hunting (threat hunting) | Proactive, hypothesis-driven search for attackers that no rule caught. |

## I-M

| Term | Meaning |
|------|---------|
| IAM | Identity and Access Management: users, groups, roles and permissions. |
| Impossible travel | Logins for one user from two places too far apart for the time between them. |
| Incident | A confirmed security event that harms or threatens confidentiality, integrity or availability. |
| Incident commander (IC) | The person who leads an incident response and makes coordination decisions. |
| Indicator of attack (IOA) | Behaviour that suggests an attack in progress, regardless of tool used. |
| Indicator of compromise (IOC) | Artefact such as an IP, domain or hash linked to malicious activity. Short-lived. |
| Initial access | How an attacker first gets in: phishing, exploited service, stolen credentials. |
| IR | Incident Response. |
| Isolation | Cutting a host off the network (except from the EDR console) to stop spread. |
| KPI | Key Performance Indicator: a measure tracked to show performance, for example mean time to respond. |
| Lateral movement | Moving from one compromised host to others (ATT&CK TA0008). |
| Living off the land (LOTL) | Using built-in tools (PowerShell, WMI, certutil) for attacks to avoid detection. |
| Log source | Any system that sends logs to the SIEM. |
| MDR | Managed Detection and Response: a provider that monitors and responds on your behalf. |
| MFA | Multi-Factor Authentication. |
| MFA fatigue | Flooding a user with push prompts until they approve one. |
| MSSP | Managed Security Service Provider. |
| MTTA / MTTD / MTTR | Mean Time To Acknowledge / Detect / Respond (or Recover). Core SOC timing metrics. |

## N-R

| Term | Meaning |
|------|---------|
| NDR | Network Detection and Response: analyses network traffic for threats. |
| Normalisation | Mapping different log formats to common field names so one query works across sources. |
| On-call | Staff reachable outside working hours to handle escalations. |
| OSINT | Open-Source Intelligence: information gathered from public sources. |
| Parsing | Extracting fields from raw log lines. Broken parsing is a frequent cause of missed alerts. |
| Password spraying | Trying one or a few common passwords across many accounts (ATT&CK T1110.003). |
| Persistence | Mechanisms an attacker uses to survive reboots: scheduled tasks, services, run keys. |
| Phishing | Deceptive messages that trick users into clicking, opening or entering credentials. |
| Playbook | Step-by-step response guide for one alert or incident type. |
| Post-incident review | Blameless meeting after an incident to capture lessons and actions. |
| Privilege escalation | Gaining higher permissions than granted (ATT&CK TA0004). |
| Purple teaming | Attackers (red) and defenders (blue) working together to test and improve detections. |
| RACI | Responsible, Accountable, Consulted, Informed: a matrix of who does what. |
| Ransomware | Malware that encrypts or steals data and demands payment. |
| Recovery | Restoring systems to normal, verified operation after an incident. |
| Retention | How long logs are kept, often split into hot (searchable) and cold (archive) tiers. |
| Root cause | The underlying reason an incident was possible, for example an unpatched VPN appliance. |
| Runbook | Technical, step-by-step procedure, often for a single task (for example "isolate a host"). |

## S-Z

| Term | Meaning |
|------|---------|
| Sandbox | Isolated environment for safely running suspicious files or URLs. |
| Severity | How serious an alert or incident is, usually P1-P4 or Critical-Low. Drives response time. |
| Shift handover | Structured transfer of open work and context between shifts. |
| Sigma | Open, vendor-neutral format for writing detection rules that convert to many SIEM languages. |
| SIEM | Security Information and Event Management: collects, stores, searches and correlates logs. |
| SLA | Service Level Agreement: agreed time to acknowledge or resolve, by severity. |
| SOAR | Security Orchestration, Automation and Response: automates enrichment and response steps. |
| SOC | Security Operations Center. |
| Supply chain attack | Compromise via a trusted vendor, software update or library. |
| Tabletop exercise | Discussion-based rehearsal of an incident scenario. |
| Tactic / technique / procedure (TTP) | How an adversary operates, from high-level goal (tactic) to specific method (procedure). |
| Telemetry | Raw activity data from endpoints, networks or cloud services. |
| Threat actor | An individual or group conducting attacks. |
| Threat intelligence (TI) | Analysed information about threats that helps you decide and act. |
| TIP | Threat Intelligence Platform: stores, scores and shares indicators and reports. |
| Tier (L1/L2/L3) | Analyst level by skill and responsibility. |
| True positive (TP) | An alert that correctly identified malicious or policy-violating activity. |
| Tuning | Changing a rule to reduce false positives without losing true positives. |
| Use case | A defined detection scenario with its rule, data sources, playbook and owner. |
| UEBA | User and Entity Behaviour Analytics: detects unusual behaviour of users and hosts. |
| Vulnerability | A weakness that could be exploited. |
| WAF | Web Application Firewall: filters HTTP traffic to web applications. |
| XDR | Extended Detection and Response: detection and response across endpoint, identity, email, cloud and network in one platform. |
| YARA | Rule language for matching patterns in files, used in malware hunting. |
| Zero-day | A vulnerability exploited before a fix is available. |
| Zero trust | Security model that verifies every request, assuming no network location is trusted. |
